# 專案憲法

## 1. 專案願景
建立一個企業級購物網站，透過 Jenkins CI/CD 實現自動化部署流程，並作為學習現代化 DevOps 實踐的教學專案。

## 2. 技術架構原則

### 2.1 前端技術規範
- **框架**: Vue 3 (Composition API)
- **樣式**: Tailwind CSS v4.*
- **UI 組件庫**: PrimeVue v4.*
- **狀態管理**: Pinia
- **響應式設計**: 必須支援 RWD (Responsive Web Design)

### 2.2 後端技術規範
- **框架**: C# .NET 10 Web API
- **架構**: RESTful API 設計模式
- **資料庫**: Microsoft SQL Server (MSSQL)

### 2.3 系統架構
- **前後端分離**: 前端與後端必須完全分離，透過 API 進行通訊
- **容器化**: 所有服務皆需 Docker 容器化部署

## 3. 功能需求原則

### 3.1 前台功能
- 客戶註冊與登入
- 商品瀏覽與搜尋
- 商品加入購物車
- 結帳功能 (僅支援貨到付款)

### 3.2 後台功能
- 商品上架管理
- 訂單管理
- 會員管理

## 4. 開發與部署規範

### 4.1 版本控制
- **平台**: GitLab
- **分支策略**: 採用 feature branch 工作流
- **提交訊息**: 使用繁體中文撰寫

### 4.2 CI/CD 流程
- **工具**: Jenkins
- **自動化流程**:
  1. 程式碼建置 (Build)
  2. 單元測試 (Test)
  3. 容器映像建置 (Docker Build)
  4. 部署至目標環境 (Deploy)

### 4.3 容器化規範
- 前端、後端、資料庫皆需建立 Dockerfile
- 使用 Docker Compose 進行多容器編排
- 參考官方 Docker Hub 映像檔配置

## 5. 溝通與文件規範

### 5.1 語言要求
- **主要語言**: 繁體中文
- **適用範圍**: 所有專案文件、程式碼註解、提交訊息、AI 溝通

### 5.2 文件結構
- 所有規格文件使用 Markdown 格式
- 技術文件需包含官網參考連結
- API 文件需完整描述端點、請求與回應格式

## 6. 學習與品質原則

### 6.1 學習目標
- 理解 Jenkins CI/CD 完整流程
- 掌握前後端分離架構實作
- 熟悉 Docker 容器化部署
- 學習 GitLab 版本控制最佳實踐

### 6.2 程式碼品質
- 遵循各技術框架的官方風格指南
- 前後端需包含單元測試
- 程式碼需通過 CI 流程檢核
