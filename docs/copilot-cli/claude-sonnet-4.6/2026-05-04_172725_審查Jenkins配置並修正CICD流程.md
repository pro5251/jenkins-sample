# 審查 Jenkins 配置並修正 CI/CD 流程

## 問題摘要

使用者要求確認 `jenkins/` 目錄中的配置是否正確，包含運行此專案 CI/CD 上版的完整流程。

---

## 審查範圍

| 檔案 | 說明 |
|---|---|
| `jenkins/Jenkinsfile` | Pipeline 定義 |
| `docker/jenkins/Dockerfile` | Jenkins 映像 |
| `docker/jenkins/jenkins.yaml` | JCasC 設定 |
| `docker/ci-cd-docker-compose.yml` | CI/CD 服務編排 |
| `docker/docker-compose.yml` | 應用服務編排 |
| `docker/.env.example` | 環境變數範本 |

---

## 發現的問題

### 🟡 問題一：`DOCKER_COMPOSE_FILE` 環境變數未使用
- `DOCKER_COMPOSE_FILE = 'docker/docker-compose.yml'` 定義後從未被引用
- 直接使用 `dir('docker')` 進入目錄執行 `docker compose build`，變數多餘

### 🟡 問題二：`IMAGE_TAG` 環境變數未接入 Docker Build
- `IMAGE_TAG = "${env.BUILD_NUMBER}"` 定義了但沒有傳給 `docker compose build`
- `docker-compose.yml` 沒有 `image:` 欄位，無法進行映像命名與推送

### 🟡 問題三：缺少 Docker Image Push 步驟
- `jenkins.yaml` 已設定 `dockerhub-credentials` 憑證
- 但 `Jenkinsfile` 完全沒有使用，無法推送至 Docker Hub

### 🟡 問題四：docker-compose.yml 密碼硬編碼
- `SA_PASSWORD=YourStrong!Passw0rd` 直接寫死在 `environment:` 區塊
- Connection string 中的密碼也是硬編碼

---

## 修正內容

### 1. `jenkins/Jenkinsfile`
- 移除未使用的 `DOCKER_COMPOSE_FILE` 環境變數
- 修正 `Docker Build` 階段：傳遞 `IMAGE_TAG` 作為環境變數
- 新增 `Docker Push` 階段（僅 `main` branch 執行）：
  - 使用 `withCredentials` 取得 `dockerhub-credentials`
  - `docker login` → `docker compose push` → `docker logout`
- 更新 `Deploy` 階段：傳遞 `DOCKER_USERNAME` 和 `IMAGE_TAG`

### 2. `docker/docker-compose.yml`
- 新增 `image:` 欄位至 backend 和 frontend 服務：
  ```yaml
  image: ${DOCKER_USERNAME:-}/jenkins-sample-backend:${IMAGE_TAG:-latest}
  image: ${DOCKER_USERNAME:-}/jenkins-sample-frontend:${IMAGE_TAG:-latest}
  ```
- `SA_PASSWORD` 改用環境變數：`${MSSQL_SA_PASSWORD:-YourStrong!Passw0rd}`
- Connection string 密碼同步改用環境變數

### 3. `docker/.env.example`
- 新增 `MSSQL_SA_PASSWORD=YourStrong!Passw0rd`

## CI/CD 完整流程（修正後）

```
Checkout → Build (parallel) → Test (parallel) → Docker Build
                                                     ↓
                                              [main branch only]
                                           Docker Push (Docker Hub)
                                                     ↓
                                           Deploy (docker compose up -d)
```

### 各階段說明

| 階段 | 說明 |
|---|---|
| Checkout | Git clone + 通知 GitLab 建置開始 |
| Build Backend | `dotnet build --configuration Release` |
| Build Frontend | `npm ci && npm run build` |
| Test Backend | `dotnet test --logger trx` |
| Test Frontend | `npm run test -- --run` |
| Docker Build | `IMAGE_TAG=xxx docker compose build` |
| Docker Push *(main only)* | Login → `docker compose push` → Logout |
| Deploy *(main only)* | `docker compose up -d` |
| post/always | `cleanWs()` 清理 workspace |
| post/success | 通知 GitLab commit status: success |
| post/failure | 通知 GitLab commit status: failed |

## 確認正確的配置

### ✅ Dockerfile
- 基礎映像：`jenkins/jenkins:lts-jdk21`
- 正確安裝：Docker CLI、.NET 10 SDK、Node.js 20 LTS
- DooD（Docker outside of Docker）設定正確：掛載 `/var/run/docker.sock`
- 所有需要的 Jenkins 插件均已安裝

### ✅ jenkins.yaml (JCasC)
- 管理員密碼透過環境變數注入 `${JENKINS_ADMIN_PASSWORD:-admin}`
- GitLab 連線正確指向 Docker 網路內部 hostname `http://gitlab:8929`
- 所有憑證均透過環境變數注入，不含硬編碼機密
- Job DSL 正確建立 `jenkins-sample` pipeline job
- 觸發條件：GitLab webhook + SCM polling (每 5 分鐘備援)

### ✅ ci-cd-docker-compose.yml
- GitLab 與 Jenkins 同在 `cicd-network`，可使用 hostname 互通
- JCasC 設定以 `ro` 模式 bind mount，方便本地調整
- 所有敏感資訊透過 `.env` 注入
