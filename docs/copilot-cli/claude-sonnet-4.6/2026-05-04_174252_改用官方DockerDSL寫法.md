# 將 Jenkinsfile Docker Push 改為官方 DSL 寫法

## 問題摘要

使用者要求將 Jenkinsfile 的 Docker Push 改為官方 Docker Pipeline DSL 寫法。

---

## 修改內容

修改檔案：`jenkins/Jenkinsfile`

### Docker Build 階段
新增 `withCredentials` 取得 `DOCKER_USER`，傳入 `docker compose build` 以正確命名映像：
```groovy
withCredentials([usernamePassword(credentialsId: 'dockerhub-credentials', ...)]) {
    sh "DOCKER_USERNAME=${DOCKER_USER} IMAGE_TAG=${IMAGE_TAG} docker compose build"
}
```

### Docker Push 階段（主要變更）

**舊寫法（Shell）：**
```groovy
sh 'echo "$DOCKER_PASS" | docker login -u "$DOCKER_USER" --password-stdin'
sh "docker compose push"
sh 'docker logout'
```

**新寫法（官方 Docker Pipeline DSL）：**
```groovy
script {
    docker.withRegistry('https://registry.hub.docker.com', 'dockerhub-credentials') {
        docker.image("${DOCKER_USER}/jenkins-sample-backend:${IMAGE_TAG}").push()
        docker.image("${DOCKER_USER}/jenkins-sample-frontend:${IMAGE_TAG}").push()
    }
}
```

**優點：**
- `docker.withRegistry` 自動處理 login / logout，不需手動管理
- 語意更清晰，符合 Jenkins 官方最佳實踐
- 參考官方文件：https://www.jenkins.io/doc/book/pipeline/docker/

---

## 設計說明

`withCredentials` 仍保留在外層，原因是需要 `DOCKER_USER` 變數來動態組成映像名稱（`username/image:tag`），`docker.withRegistry` 本身只負責認證，不提供 username 變數。
