# 操作指南：GitLab + Jenkins CI/CD 環境建置

**專案**：jenkins-sample  
**目標**：本地 Docker 環境 — GitLab + Jenkins 整合，推送程式碼自動觸發 CI/CD Pipeline

---

## 環境架構

```
┌─────────────────────────────────────────────────┐
│              Docker infra-network               │
│                                                 │
│  ┌──────────────┐      ┌──────────────────────┐ │
│  │   GitLab CE  │◄─────│      Jenkins         │ │
│  │  :8929 (HTTP)│      │  :8080 (Web UI)      │ │
│  │  :2224 (SSH) │      │  :50000 (Agent)      │ │
│  └──────────────┘      └──────────────────────┘ │
└─────────────────────────────────────────────────┘

本機存取：
  GitLab  → http://localhost:8929  (root / password)
  Jenkins → http://localhost:8080  (admin / admin)
```

---

## 前置需求

- Docker Desktop（或 Docker Engine + Compose Plugin）
- Git
- `curl`（setup-gitlab.sh 腳本使用）

## 一、首次環境建置

### 1. 啟動 GitLab + Jenkins

```bash
cd /path/to/jenkins-sample/docker

# 建置 Jenkins 映像並啟動所有 infra 服務（背景執行）
docker compose -f docker-compose.infra.yml up -d --build
```

> ⚠️ **GitLab 首次啟動約需 3–5 分鐘**，請等待完全就緒再進行下一步。

確認 GitLab 已就緒：

```bash
# 出現 {"status":"ok"} 即代表就緒
curl -s http://localhost:8929/-/health
```

或觀察 log：

```bash
docker logs -f gitlab 2>&1 | grep -E "gitlab Reconfigured|GitLab OK"
```

---

### 2. 執行 POC 自動設定腳本

```bash
bash /path/to/jenkins-sample/docker/setup-gitlab.sh
```

腳本會自動完成以下事項：

| 步驟 | 說明 |
|------|------|
| ① | 等待 GitLab 服務就緒 |
| ② | 設定 root 密碼（預設 `password`），建立 Personal Access Token |
| ③ | 建立 GitLab 專案 `jenkins-sample` |
| ④ | 設定 git remote `gitlab` 並推送程式碼至 `main` 分支 |
| ⑤ | 更新 Jenkins 中的 `gitlab-api-token` 憑證 |
| ⑥ | 在 GitLab 專案設定 Webhook → Jenkins |

腳本執行完畢後，終端機會顯示如下摘要：

```
════════════════════════════════════════════════════════
✅ POC 設定完成！

📋 服務 URL：
   GitLab  : http://localhost:8929  (帳號: root / 密碼: password)
   Jenkins : http://localhost:8080  (帳號: admin / 密碼: admin)

📋 GitLab API Token: glpat-xxxxxxxxxxxx
════════════════════════════════════════════════════════
```

---

### 3. 確認 Jenkins Job

1. 開啟 `http://localhost:8080`，使用 `admin / admin` 登入
2. 確認首頁出現 **`jenkins-sample`** Pipeline Job
3. 點入 Job → **「立即建置」** 手動觸發一次，驗證流程正常

> 若 Job 未出現，請至 **Manage Jenkins → Configuration as Code → Reload existing configuration** 重新套用 JCasC。

## 二、日常操作

### 推送程式碼觸發 CI/CD

```bash
cd /path/to/jenkins-sample

# 推送到本地 GitLab（會自動觸發 Jenkins Webhook）
git push gitlab <當前分支>:main
```

### 查看 Pipeline 狀態

| 方式 | URL |
|------|-----|
| Jenkins Pipeline 視圖 | http://localhost:8080/job/jenkins-sample |
| GitLab Commit 狀態 | http://localhost:8929/root/jenkins-sample/-/pipelines |

## 三、環境管理

### 停止所有 infra 服務

```bash
cd docker
docker compose -f docker-compose.infra.yml down
```

### 停止並清除所有資料（重置）

```bash
cd docker
docker compose -f docker-compose.infra.yml down -v
```

> ⚠️ `-v` 會刪除 GitLab 與 Jenkins 的 Docker Volume，所有資料將遺失，需重新執行設定腳本。

### 重新啟動（保留資料）

```bash
cd docker
docker compose -f docker-compose.infra.yml start
```

### 查看容器狀態與 Log

```bash
# 查看容器狀態
docker compose -f docker-compose.infra.yml ps

# 查看 Jenkins log
docker logs -f jenkins

# 查看 GitLab log
docker logs -f gitlab
```

## 四、Jenkins JCasC 設定說明

設定檔路徑：`docker/jenkins/jenkins.yaml`

| 設定項目 | 說明 | 預設值 |
|----------|------|--------|
| Jenkins 管理員密碼 | `JENKINS_ADMIN_PASSWORD` 環境變數 | `admin` |
| GitLab 使用者 | `GITLAB_USER` | `root` |
| GitLab 密碼 | `GITLAB_PASSWORD` | `password` |
| GitLab API Token | `GITLAB_API_TOKEN`（由腳本自動填入） | 空 |
| GitLab 連線 URL | 固定為 `http://gitlab:8929`（Docker 內部） | — |

修改環境變數方式（建立 `.env` 檔）：

```bash
# docker/.env
JENKINS_ADMIN_PASSWORD=mypassword
GITLAB_ROOT_PASSWORD=mypassword
GITLAB_API_TOKEN=glpat-xxxxxxxxxxxx
```

修改 `jenkins.yaml` 後，在 Jenkins UI 中套用：
**Manage Jenkins → Configuration as Code → Reload existing configuration**

## 五、Pipeline 流程說明

`jenkins/Jenkinsfile` 定義的完整 CI/CD 流程：

```
Checkout
  └─ 通知 GitLab commit 狀態為 running

Build（並行）
  ├─ Build Backend：dotnet build --configuration Release
  └─ Build Frontend：npm ci && npm run build

Test（並行）
  ├─ Test Backend：dotnet test --logger trx
  └─ Test Frontend：npm run test -- --run

Docker Build
  └─ docker compose build（需要 dockerhub-credentials）

Docker Push（僅 main branch）
  └─ 推送映像至 Docker Hub

Deploy（僅 main branch）
  └─ docker compose up -d

Post
  ├─ success → 通知 GitLab commit 狀態為 success
  ├─ failure → 通知 GitLab commit 狀態為 failed
  └─ always  → cleanWs()（清除 workspace）
```

> **POC 說明**：Docker Push / Deploy stage 只在 `main` branch 執行，且需要設定 `dockerhub-credentials`。POC 驗證期間不需要設定，Build + Test 流程即可正常運行。

## 六、常見問題排查

### Q: GitLab 啟動後無法訪問

```bash
# 確認容器正常運行
docker ps | grep gitlab

# 確認 health 狀態
curl http://localhost:8929/-/health
```

GitLab 完全啟動可能需要 3–5 分鐘，請耐心等待。

---

### Q: Jenkins Job `jenkins-sample` 沒有出現

原因：JCasC 的 Job DSL 在 GitLab 尚未就緒時可能未完全套用。

解法：

1. 等待 GitLab 完全啟動
2. Jenkins UI → **Manage Jenkins → Configuration as Code → Reload existing configuration**

---

### Q: Jenkins 建置失敗：無法 clone 程式碼

確認步驟：

```bash
# 確認 GitLab 上有 jenkins-sample 專案
curl -s http://localhost:8929/api/v4/projects \
  -H "PRIVATE-TOKEN: <your-token>" | python3 -m json.tool | grep name

# 確認 Jenkins credentials 設定
# Jenkins UI → Manage Jenkins → Credentials → System → Global credentials
# 確認 gitlab-credentials 的帳號密碼正確
```

---

### Q: Webhook 沒有觸發 Jenkins 建置

```bash
# 確認 Webhook 設定
curl -s http://localhost:8929/api/v4/projects/root%2Fjenkins-sample/hooks \
  -H "PRIVATE-TOKEN: <your-token>" | python3 -m json.tool
```

在 GitLab 專案 → Settings → Webhooks → Test 手動發送測試事件。
